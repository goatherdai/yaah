Supervise running sub-agents, selected by `action`. `list_scopes` shows every scope and its state; `status` reports the supervision system status.

`snapshot` reads a compact per-agent view of what the sub-agents are doing, batched into one poll: for each agent its role, scope, workdir, whether it is still running, how long it has been (or ran), its total call and error counts, the most recent tool call with its arguments, the trailing tool calls, and the files its successful write/edit/append/patch/delete calls named. The view is read-only — it is assembled from the trace facts each agent already wrote, so polling never disturbs the agent it describes — and every axis is capped: at most 50 agents, the last 25 calls per agent, and a bounded rendering. An agent whose trace could not be read appears with a `note` explaining why instead of failing the poll. A finished agent stays visible for a short window after its dispatch ends. The file list is the set of paths named by successful mutating calls, not a diff: a file written and then deleted still appears, and writes made through the shell are not listed.

`inject` records `guidance` in the trace and delivers it to the scope named by `scope_id`. Delivery is best-effort: if the scope has no active run, or the supervision bridge is not active, the guidance is trace-only; if the run's steering buffer is full it is recorded but not consumed, so consider halting or retrying later. Injecting into the session root steers the session itself.

`halt` asks the scope to stop: it cancels a running loop, waits up to 10 seconds for it to quiesce, then records the kernel halt. A halt is not an instant stop. It reports whether the run stopped after cancellation, was cancelled but had not stopped within the bound (an in-flight tool may be interrupted by sandbox teardown), or had no active run to cancel (or the bridge was inactive) and was recorded in the trace only. Halting the session root requires `agents.default.supervisor_halt_root`; without that opt-in it is refused because it stops the session's current run and ends scope-tree supervision for the process. Halt a sub-agent scope when you only need to stop one dispatch.

`redirect` claims the scope's current run, records `guidance` as the successor's first message, cancels the current run, and returns immediately — it never waits for the replacement. When the cancelled run returns, the dispatch adopts a fresh loop on the same scope with that guidance, so a redirect replaces the conversation rather than steering it. The claim is single-winner per run: a second redirect while one is in progress reports that instead of starting another replacement, and a scope with no active run reports that nothing was claimed. Redirecting the session root requires `agents.default.supervisor_halt_root`, like halt, because it stops the session's current run and no dispatch loop exists to adopt a replacement.
